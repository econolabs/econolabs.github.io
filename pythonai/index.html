Токены и эмбеддинги — как AI понимает текст

Токены и эмбеддинги — как AI понимает текст

Прежде чем AI сможет работать с текстом, он превращает его в числа. Токены — это «кирпичики» текста, а эмбеддинги — их числовые координаты в пространстве смыслов.

# Токенизация:
«Привет, мир!» → [«Привет», «,», « мир», «!»] — 4 токена

# Эмбеддинг (условный):
«кот» → [0.12, -0.34, 0.56, ..., 0.78] # 384 или 768 чисел
«кошка» → [0.13, -0.35, 0.55, ..., 0.79] # почти такой же вектор

Токен:

  • Минимальная единица текста для LLM
  • Это может быть: слово, часть слова, знак препинания, пробел
  • За токены платят при использовании API
  • 1 токен ≈ 0.75 слова на русском

Эмбеддинг (вектор):

  • Числовое представление смысла
  • Похожие тексты → близкие векторы
  • Размерность: от 384 (small) до 1536+ (large)
  • Основа для поиска по смыслу

Векторы и меры сходства — как сравнивать смыслы

Чтобы найти похожие документы, нужно уметь измерять расстояние между векторами. Главный инструмент — косинусное сходство.

# Косинусное сходство (cosine similarity):
cos(θ) = (A·B) / (|A| × |B|)
результат: от 0 (не похожи) до 1 (очень похожи)

# Пример:
«кот спит» и «кошка отдыхает» → сходство 0.95
«кот спит» и «я люблю пиццу» → сходство 0.12

Косинусное сходство:

  • Игнорирует длину вектора (важен только угол)
  • Стандарт для текстовых эмбеддингов
  • 1 = одинаковый смысл, 0 = никакой связи

Другие меры:

  • Евклидово расстояние: прямое расстояние между точками
  • Манхэттенское расстояние: сумма модулей разниц
  • Для текстов: косинусное — лучший выбор

RAG — как заставить AI отвечать по вашим документам

RAG (Retrieval-Augmented Generation) — подход, при котором AI сначала ищет ответ в вашей базе знаний, а потом отвечает, опираясь на найденные факты. Это как «открытая книжка на экзамене».

1. Поиск (Retrieval): вопрос → эмбеддинг → поиск похожих чанков
2. Контекст: найденные чанки добавляются в промпт
3. Генерация: LLM отвечает ТОЛЬКО по контексту

Зачем нужен RAG:

  • LLM знает только то, на чём обучена (данные до 2023–2024)
  • Ваши документы (законы, инструкции) — свежие и специфичные
  • RAG добавляет актуальные факты в контекст
  • Снижает галлюцинации (выдумки)

Ключевые понятия RAG:

  • Чанкинг: нарезка документов на кусочки
  • Векторная БД: хранилище эмбеддингов
  • Контекстное окно: сколько токенов помещается
  • Галлюцинация: когда AI уверенно врёт

Чанкинг и контекстное окно — как уместить всё в память

У LLM есть ограничение на количество токенов за один вызов — это контекстное окно. Чтобы загрузить в него большой документ, его нужно нарезать на чанки.

# Пример чанкинга:
Документ (10 000 токенов) → чанки по 500 токенов + перекрытие 50
Чанк 1: [0...500]
Чанк 2: [450...950] ← перекрытие сохраняет контекст на границе
Чанк 3: [900...1400]
...

Рекомендации по чанкингу:

  • 500–1500 токенов на чанк
  • Перекрытие (overlap) 10–20%
  • Резать по границам абзацев/предложений
  • Семантический чанкинг (по смыслу) — лучше, но сложнее

📌 Контекстное окно моделей:

  • GPT-3.5: 4K–16K токенов
  • GPT-4 Turbo: 128K токенов
  • Gemini 1.5 Pro: 2M токенов (целые книги!)
  • DeepSeek-V3: 128K–1M токенов

Векторные БД и поиск — как найти нужное среди миллионов

Обычные SQL-базы данных ищут точные совпадения. Векторные БД ищут похожие по смыслу — среди миллиардов векторов за доли секунды.

# Как работает векторный поиск:
Запрос «налоги для ИП» → эмбеддинг запроса
↓
Векторная БД ищет ближайшие векторы (косинусное сходство)
↓
Возвращает: «налоговая база ИП», «страховые взносы ИП», «УСН для ИП»

Популярные векторные БД:

  • FAISS (Facebook) — для больших объёмов
  • Chroma — простая, для прототипов
  • Qdrant — с фильтрацией и API
  • Milvus — enterprise-решение

Ключевая технология — ANN:

  • ANN (Approximate Nearest Neighbor)
  • Не точный, а «приближённый» поиск
  • Жертвует точностью ради скорости (x100–x1000)
  • Для RAG этого достаточно

LLM и галлюцинации — когда AI уверенно врёт

LLM (Large Language Model) — большая языковая модель. Она обучена предсказывать следующее слово, а не проверять факты. Отсюда галлюцинации.

# Пример галлюцинации:
Вопрос: «Какой документ нужен для вычета на ребёнка?»
Ответ LLM (без RAG): «Форма КНД-1151080»
Реальность: такой формы НЕ СУЩЕСТВУЕТ!

# Как бороться:
Промт: «Отвечай ТОЛЬКО по контексту. Если не знаешь — скажи "не знаю"»

Почему LLM галлюцинирует:

  • Цель LLM — правдоподобный текст, а не истина
  • Если модель не знает ответа — она «додумывает»
  • Отсутствие контекста или плохой промпт

Как снизить галлюцинации:

  • ✅ RAG (дать факты из надёжного источника)
  • ✅ Запретить отвечать без контекста
  • ✅ Низкая температура (0.0–0.2) для фактов
  • ✅ Попросить указать источник (цитату из документа)

Гибридный поиск и переранжирование — как улучшить качество поиска

Гибридный поиск и переранжирование — как улучшить качество поиска

Векторный поиск хорош по смыслу, но плох с точными терминами. Гибридный поиск объединяет его с полнотекстовым. А переранжирование — финальная «шлифовка» результатов.

# Гибридный поиск:
Векторный поиск (по смыслу) + Полнотекстовый (BM25 по ключевым словам)
↓ объединение через RRF
Результат: и «синонимы», и «точный термин»

# Переранжирование (Reranking):
Быстрый поиск (50 кандидатов) → Reranker (медленный, точный) → Топ-5

Гибридный поиск — когда нужен:

  • Пользователь ищет точный номер закона («ст. 137 УК РФ»)
  • В тексте есть редкие термины (ИНН, ОГРН, SNILS)
  • Важна и смысловая близость, и точное совпадение

Переранжирование — зачем:

  • Первичный поиск быстрый, но не очень точный (ANN)
  • Reranker (кросс-энкодер) оценивает точнее
  • Пример: reranker = CrossEncoder('intfloat/e5-mistral-7b')
  • Повышает качество топа-5 на 20–30%

📊 Метрики качества RAG — как измерить, работает ли система

RAG можно улучшать только если его измерять. Основные метрики делятся на поиск (retrieval) и генерацию (generation).

# Метрики поиска:
- Precision@k: сколько из k найденных — релевантны
- Recall@k: сколько релевантных найдено из всех
- MRR: насколько высоко первый релевантный результат

# Метрики генерации:
- Faithfulness: ответ верен контексту?
- Ответ по эталону: ROUGE, BERTScore, LLM-as-a-judge

Для поиска (retrieval):

  • Recall@5: есть ли ответ в топ-5 чанках?
  • Precision@3: сколько из топ-3 — нужные?
  • MRR: важен порядок результатов

Для генерации (generation):

  • Faithfulness: AI не придумал лишнего?
  • Ответ по эталону: совпадает с идеалом?
  • LLM-as-a-judge: GPT оценивает ответ (от 1 до 5)

📝 Учебный мини‑RAG на NumPy (работает в JupyterLite) 

import numpy as np
import pandas as pd

# 1. Загружаем готовые эмбеддинги (заранее сгенерированы)
df = pd.read_csv('embeddings.csv')  # колонки: text, emb_0, emb_1, ..., emb_383
texts = df['text'].tolist()
vectors = df.iloc[:, 1:].values.astype(np.float32)

# 2. Функция косинусного сходства
def cosine_sim(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

# 3. Поиск k ближайших соседей (наивный kNN)
def knn(query_vec, vectors, k=3):
    sims = [cosine_sim(query_vec, v) for v in vectors]
    best_idx = np.argsort(sims)[-k:][::-1]
    return best_idx, [sims[i] for i in best_idx]

# 4. Пример использования
query = "как оформить загранпаспорт"
# query_vec — эмбеддинг запроса (тоже из CSV или внешнего API)
idx, scores = knn(query_vec, vectors, k=3)
for i, score in zip(idx, scores):
    print(f"{score:.3f} — {texts[i]}")

Тема 1. Векторы: что это и зачем они нейросетям

Важно: Вектор — это упорядоченный набор чисел. В нейросетях текст, изображение или аудио превращаются в вектор — «цифровой слепок смысла».
Определение вектора с точки зрения математики:

Вектор — это элемент линейного пространства, который задаётся координатами. В прикладных задачах вектор — это просто строка или столбец чисел. 

v = [0.12, -0.34, 0.56, 0.78, -0.21]  # вектор размерности 5
Как текст становится вектором (эмбеддингом):
  • Токенизация: текст разбивается на токены (слова, части слов).
  • Преобразование в числа: нейросеть-энкодер переводит токены в набор чисел.
  • Результат: эмбеддинг — вектор фиксированной размерности (например, 384, 768 или 1536 чисел).
Почему размерность важна:
  • Маленькая размерность (64–128): быстро, но теряется много смысла.
  • Большая размерность (768–1536): точнее передаёт смысл, но требует больше памяти и вычислений.
Пример для ИТ-студента: Эмбеддинг предложения «кот спит на диване» — это массив чисел типа float32 размером 768. Два семантически близких предложения будут иметь почти одинаковые векторы.

Тема 2. Матрицы: как хранить много векторов

Важно: Матрица — это просто таблица чисел, где каждая строка или столбец может быть отдельным вектором. В векторных базах данных тысячи и миллионы векторов хранятся именно в матрицах.
Определение матрицы:

Матрица размером m × n — это прямоугольная таблица, содержащая m строк и n столбцов. Каждая строка матрицы — это отдельный вектор размерности n. 

# Матрица 3 × 4 (3 вектора размерности 4)
         [[0.1, 0.2, 0.3, 0.4],   # вектор 1
          [0.5, 0.6, 0.7, 0.8],   # вектор 2
          [0.9, 1.0, 1.1, 1.2]]   # вектор 3
Как матрицы используются в RAG:
  • Хранение эмбеддингов: Все чанки документов превращаются в векторы и образуют матрицу.
  • Пакетные операции: За один раз можно вычислить сходство между запросом и тысячами векторов.
  • Снижение размерности: Матрицы позволяют применять PCA (метод главных компонент) для визуализации векторов на плоскости.
Пример из реальной задачи:

База знаний госоргана содержит 10 000 документов. Каждый документ превращён в эмбеддинг размерности 384. Итоговая матрица имеет размер 10 000 × 384 чисел. При поиске запрос (вектор 1 × 384) умножается на эту матрицу для получения косинусного сходства.

Формула для ИТ-студента: Матрица эмбеддингов E размера N × d, где N — количество документов, d — размерность эмбеддинга.

Тема 3. Косинусное сходство: как сравнивать векторы

Важно: Косинусное сходство измеряет угол между двумя векторами. Чем меньше угол, тем более похожи тексты по смыслу.
Формула косинусного сходства:
cos(θ) = (a · b) / (||a|| × ||b||)

где a · b — скалярное произведение векторов,
||a|| — длина (норма) вектора a
Как это работает на практике:
  • Результат косинусного сходства лежит в диапазоне от 0 до 1 (если векторы неотрицательные).
  • cos = 1: векторы сонаправлены — текст про одно и то же.
  • cos = 0: векторы перпендикулярны — смыслы совершенно разные.
  • cos = -1: векторы противоположны — тексты антагонистичны (редко для эмбеддингов).
Пример из жизни:

Эмбеддинг «кот спит на диване» и «кошка отдыхает на софе» дадут косинусное сходство ≈ 0.95 — почти одинаковый смысл. Эмбеддинг «кот спит» и «я люблю программировать» даст сходство ≈ 0.1.

Почему косинусное, а не евклидово расстояние:
  • Евклидово расстояние зависит от длины вектора.
  • Косинусное сходство учитывает только направление, что важно для текстов: короткий текст может быть очень похож на длинный по смыслу.
Математическая формулировка: Косинусное сходство — это нормализованное скалярное произведение.

Тема 4. Линейная алгебра в RAG: матричное умножение

Важно: Поиск ближайших соседей — это умножение матрицы эмбеддингов на вектор запроса. Линейная алгебра лежит в основе любой векторной базы данных.
Поиск через скалярное произведение:

Если эмбеддинги нормализованы (имеют длину 1), то косинусное сходство превращается в скалярное произведение. Поиск — это умножение матрицы E на вектор q. 

# E — матрица эмбеддингов (N × d)
# q — вектор запроса (1 × d)
# Результат scores = E × q^T  — вектор длиной N (сходство с каждым документом)
Проблема масштабирования (почему нужен FAISS):
  • Наивный поиск: для каждого запроса нужно вычислить сходство со всеми N векторами. Сложность O(N × d).
  • N = 1 млн, d = 768: нужно 768 млн операций на запрос. Это медленно.
  • Решение — ANN (приближённый поиск): алгоритмы вроде HNSW строят графы и ищут не по всей матрице, а по «подозрительным» соседям. Сложность падает до O(log N).
Что изучать дальше из линейной алгебры:
  • SVD (сингулярное разложение): лежит в основе LSA (латентно-семантического анализа).
  • PCA (метод главных компонент): снижение размерности для визуализации и ускорения.
  • QR-разложение: используется в некоторых ANN-алгоритмах.
Связь с курсом математики: Операции с матрицами и векторами, которые вы изучаете на линейной алгебре, — это именно то, что выполняется миллиарды раз при работе RAG-систем.

Тема 5. Векторные базы данных: мост между матрицами и поиском

Важно: Векторная база данных — это специализированное хранилище, которое внутри использует матрицы и алгоритмы линейной алгебры для быстрого поиска похожих векторов.
Как устроена векторная БД изнутри:
  • Матрица эмбеддингов хранится в памяти или на диске.
  • Для ускорения поиска строятся индексы (HNSW, IVF, PQ) — дополнительные структуры данных, основанные на графах или кластеризации.
  • При запросе индекс быстро находит кандидатов, затем вычисляются точные расстояния.
Пример: индекс IVF (Inverted File Index)
1. Все N векторов разбиваются на K кластеров (k-means).
2. При запросе определяются ближайшие кластеры.
3. Поиск выполняется только внутри этих кластеров.
Сравнение с классическими базами данных:
SQL / Реляционная БД:
  • Ищет точные совпадения (WHERE name = "Иванов")
  • Индексы — B-tree, хеш-таблицы
  • Не умеет искать «похожее»
Векторная БД (Chroma, FAISS, Qdrant):
  • Ищет по смыслу (косинусное сходство)
  • Индексы — HNSW, IVF, PQ
  • Оптимизирована для многомерных данных
Почему нельзя использовать обычную SQL-БД:
  • Индексы B-tree работают хорошо только для одномерных данных.
  • Для 768-мерных векторов полный перебор занимает секунды на миллион записей, а индекс HNSW — миллисекунды.
Итог для студента: Понимание матриц и векторов — это фундамент. Векторная БД — это надстройка, которая делает возможным поиск по смыслу среди миллионов документов за доли секунды.
