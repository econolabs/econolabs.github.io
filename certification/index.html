Тема 1. Основы качества и стандартизации в ИТ

1.1 Понятие качества информационной системы

Качество ИС — это совокупность свойств и характеристик системы, которые определяют её способность удовлетворять установленные или предполагаемые потребности пользователей.

Ключевая идея: Качество ИС не сводится только к отсутствию ошибок. Это комплексная характеристика, включающая функциональность, надёжность, производительность, удобство использования и безопасность.
Аспект качества Описание Пример
Функциональность Способность системы выполнять требуемые функции Интернет-банк позволяет переводить деньги
Надёжность Способность системы сохранять работоспособность Система не падает при 1000 одновременных запросов
Производительность Скорость выполнения операций Страница загружается за 0.5 секунды
Удобство использования Интуитивность интерфейса Пользователь находит нужную функцию без инструкции
Безопасность Защита данных от несанкционированного доступа Данные шифруются, пароли хранятся в хешированном виде
📌 Важно: Качество ИС — это не абсолютная характеристика, а соответствие требованиям. Система, идеальная для одной задачи, может быть неприемлемой для другой.

1.2 Жизненный цикл ПО и обеспечение качества

Жизненный цикл ПО (ЖЦ ПО) — это последовательность этапов, которые проходит система от концепции до вывода из эксплуатации.

Этап ЖЦ Действия по обеспечению качества
Анализ требований Проверка полноты и непротиворечивости требований
Проектирование Архитектурный ревью, проверка на соответствие стандартам
Разработка Статический анализ кода, ревью кода, модульное тестирование
Тестирование Функциональное, интеграционное, нагрузочное тестирование
Внедрение Проверка установки, миграции данных, обучение
Эксплуатация Мониторинг, сбор метрик, обработка инцидентов
Сопровождение Устранение дефектов, улучшение функциональности
Принцип: Чем раньше дефект обнаружен, тем дешевле его исправление. Качество закладывается на всех этапах, а не только при тестировании.

1.3 Модели качества ПО: ISO 25010

ISO 25010 — международный стандарт, определяющий модель качества программного обеспечения. Он заменил ISO 9126.

Характеристика Подхарактеристики
Функциональная пригодность Полнота, корректность, целесообразность
Производительность Временное поведение, пропускная способность, эффективность ресурсов
Совместимость Взаимодействие, совместимость с другими системами
Удобство использования Обучаемость, понятность, эстетика, доступность
Надёжность Доступность, восстановляемость, устойчивость к ошибкам
Безопасность Конфиденциальность, целостность, отказоустойчивость
Поддерживаемость Модульность, анализируемость, модифицируемость, тестируемость
Переносимость Адаптируемость, устанавливаемость, заменяемость
Важно: Модель ISO 25010 используется для систематической оценки качества и является основой для сертификации.

1.4 Стандарты в области информационных технологий

Стандартизация — это деятельность по установлению правил и характеристик для добровольного многократного использования.

Стандарт Область применения Описание
ISO 9001 Системы менеджмента качества Базовый стандарт для СМК всех организаций
ISO 27001 Информационная безопасность Система менеджмента информационной безопасности (СМИБ)
ISO 25010 Качество ПО Модель качества программных продуктов
ГОСТ 34.601-90 Автоматизированные системы Этапы создания АС
ГОСТ 19.ххх ЕСПД Единая система программной документации
IEEE 829 Тестирование ПО Документирование тестирования

1.5 Системы менеджмента качества: ISO 9001

ISO 9001 — это международный стандарт, устанавливающий требования к системе менеджмента качества (СМК). Он применим к любой организации, включая ИТ-компании.

Принципы ISO 9001:
  • Ориентация на потребителя
  • Лидерство руководителей
  • Вовлечение персонала
  • Процессный подход
  • Улучшение
  • Принятие решений на основе фактов
  • Управление отношениями с поставщиками
Для ИТ-компаний: Внедрение ISO 9001 помогает систематизировать процессы разработки, повысить качество продукта и выстроить доверие с заказчиками.

1.6 Международные стандарты информационной безопасности: ISO 27001

ISO 27001 — стандарт, определяющий требования к системе менеджмента информационной безопасности (СМИБ).

Область ISO 27001 Описание
Управление активами Идентификация и защита информационных активов
Управление доступом Контроль доступа к информации и системам
Управление инцидентами Обнаружение и реагирование на инциденты безопасности
Обеспечение непрерывности Планирование восстановления после сбоев
Управление поставщиками Оценка рисков, связанных с подрядчиками
Сертификация по ISO 27001 — это подтверждение того, что компания обеспечивает надёжную защиту данных клиентов.

1.7 Отечественные ГОСТы для информационных систем

ГОСТы — это государственные стандарты РФ, обязательные для применения в определённых сферах.

ГОСТ Область применения
ГОСТ 34.601-90 Стадии создания автоматизированных систем
ГОСТ 34.603-92 Виды испытаний автоматизированных систем
ГОСТ 19.101-77 Виды программных документов (ЕСПД)
ГОСТ Р ИСО/МЭК 12207 Процессы жизненного цикла ПО
ГОСТ Р 54800-2011 Качество ПО. Метрики

1.8 Критерии качества информационных систем

Критерии качества — это измеримые показатели, по которым оценивается соответствие системы требованиям.

Критерий Измерение Пример цели
Доступность % времени работы 99.9% (время простоя ≤ 8.7 часов в год)
Время отклика Среднее время ответа < 200 мс для 95% запросов
Плотность дефектов Ошибок на KLOC < 0.5 ошибок на 1000 строк кода
Покрытие тестами % покрытия кода > 80% покрытия
Удовлетворённость пользователей CSAT, NPS NPS > 50
Критерии должны быть SMART: конкретными, измеримыми, достижимыми, релевантными и ограниченными по времени.

1.9 Метрики качества программного обеспечения

Метрики качества — это количественные показатели, используемые для оценки различных аспектов ПО.

Метрика Описание Характеристика ISO 25010
Сложность кода (Cyclomatic Complexity) Количество независимых путей в программе Анализируемость, модифицируемость
Связность (Cohesion) Степень, с которой элементы модуля связаны Модульность
Сцепление (Coupling) Степень зависимости между модулями Модульность, тестируемость
Покрытие кода (Code Coverage) % кода, покрытого тестами Тестируемость
Технический долг (Technical Debt) Время на исправление недостатков кода Поддерживаемость
MTTF / MTTR Среднее время до отказа / восстановления Надёжность, восстановляемость
Метрики должны собираться автоматически и регулярно, чтобы отслеживать тенденции.

1.10 Обеспечение качества на этапах разработки

Обеспечение качества (Quality Assurance, QA) — это систематическая деятельность, направленная на создание уверенности в том, что продукт будет соответствовать требованиям.

Этап разработки Методы QA Результат
Планирование Определение метрик качества, планирование тестирования Стратегия качества
Проектирование Архитектурный ревью, проверка на паттерны Качественная архитектура
Разработка Ревью кода, статический анализ, модульные тесты Чистый, рабочий код
Тестирование Функциональное, интеграционное, нагрузочное тестирование Верифицированный продукт
Внедрение Тестирование установки, обучение пользователей Успешный запуск
Эксплуатация Мониторинг, сбор отзывов, анализ инцидентов Непрерывное улучшение
Ключевой принцип QA: качество встроено в процесс, а не проверяется в конце.

Тема 2. Сертификация информационных систем

2.1 Понятие и цели сертификации

Сертификация — это процедура подтверждения соответствия продукции, услуги или системы установленным требованиям.

Основные цели сертификации:
  • Обеспечение доверия потребителей к продукту
  • Подтверждение соответствия нормативным требованиям
  • Повышение конкурентоспособности
  • Снижение рисков для бизнеса и пользователей
  • Получение доступа к определённым рынкам
В ИТ-сфере сертификация часто является обязательным условием для работы с государственными заказчиками.

2.2 Объекты сертификации в информационных технологиях

Объект сертификации Пример Стандарт
Программное обеспечение Операционные системы, ERP-системы ISO 25010, ГОСТ 34
Аппаратно-программные комплексы Серверы, СХД, сетевые устройства ГОСТ Р, технические регламенты
Системы защиты информации Средства криптографии, IDS/IPS ФСТЭК, ISO 27001
Информационные системы ГИС, банковские системы ГОСТ 34, ISO 25010
Базы данных SQL, NoSQL системы ISO 25010
Веб-приложения Интернет-магазины, порталы OWASP, ISO 25010

2.3 Системы сертификации в РФ и мире

Система сертификации Юрисдикция Применение в ИТ
ГОСТ Р Россия Обязательная сертификация продукции
ФСТЭК России Россия Сертификация СЗИ, аттестация объектов информатизации
Минцифры Россия Аккредитация ИТ-компаний

2.4 Сертификация систем защиты информации

Сертификация СЗИ — это подтверждение соответствия средств защиты информации требованиям по безопасности.

Ключевые регуляторы в РФ:
  • ФСТЭК России — сертификация СЗИ для государственных информационных систем
  • Минцифры — аккредитация и подтверждение соответствия
  • Банк России — для финансовых организаций
Уровень сертификации Описание Пример
Уровень 1 Средства, не требующие специальной защиты Антивирусы, брандмауэры
Уровень 2 Средства, используемые в государственных системах Средства аутентификации, VPN
Уровень 3 Средства для систем, обрабатывающих гостайну Сертифицированные криптосредства

2.5 Органы по сертификации

Орган по сертификации — это юридическое лицо, имеющее право проводить сертификацию и выдавать сертификаты.

Требования к органам по сертификации:
  • Аккредитация в национальной системе (в РФ — Росаккредитация)
  • Независимость от производителя и потребителя
  • Наличие квалифицированного персонала
  • Соблюдение конфиденциальности
Примеры органов в РФ: ФГУП «Главный центр специальной связи», ООО «Центр сертификации», АНО «Центр сертификации информационных технологий».

2.6 Процедура сертификации информационных систем

Этап Действия Результат
1 Подача заявки Заполнение заявки, предоставление документов Заключение договора с органом по сертификации
2 Экспертиза документов Анализ технической документации, требований Решение о возможности проведения сертификации
3 Испытания Тестирование ИС, проверка соответствия Протокол испытаний
4 Анализ результатов Оценка результатов испытаний, акта проверки Решение о выдаче сертификата
5 Выдача сертификата Оформление и регистрация сертификата Сертификат соответствия
6 Инспекционный контроль Периодическая проверка соответствия Поддержание сертификата в силе

2.7 Виды сертификатов в ИТ-сфере

Вид сертификата Описание Пример
Сертификат соответствия Подтверждение, что продукт соответствует стандарту ISO 9001:2015
SSL-сертификат Подтверждение подлинности веб-сайта и шифрование SSL/TLS сертификат для сайта
Сертификат разработчика (Code Signing) Подтверждение авторства и целостности кода Сертификат для подписи .exe файлов
Сертификат СЗИ Подтверждение безопасности средств защиты Сертификат ФСТЭК на антивирус
Сертификат менеджмента ИБ Подтверждение внедрения СМИБ ISO 27001:2022

2.8 Сертификация веб-приложений

Сертификация веб-приложений — это процесс подтверждения безопасности и качества веб-систем.

Ключевые аспекты сертификации веб-приложений:
  • Проверка на уязвимости (OWASP Top 10)
  • Оценка производительности и масштабируемости
  • Проверка соответствия требованиям по защите персональных данных (152-ФЗ)
  • Аудит кода и конфигурации
Стандарты: OWASP ASVS, ISO 25010, PCI DSS (для платёжных систем).

2.9 Сертификация SSL/TLS

SSL/TLS сертификаты — это цифровые сертификаты, которые обеспечивают шифрование соединения и проверку подлинности сервера.

Тип сертификата Уровень проверки Использование
DV (Domain Validation) Проверка владения доменом Личные сайты, блоги
OV (Organization Validation) Проверка организации Бизнес-сайты
EV (Extended Validation) Полная проверка организации Банки, интернет-магазины
Wildcard Защита всех поддоменов Крупные проекты с множеством поддоменов
Multi-Domain (SAN) Защита нескольких доменов Компании с несколькими сайтами
SSL-сертификаты являются обязательными для всех сайтов, работающих с персональными данными.

Тема 3. Методы и средства контроля качества ИС

3.1 Статический анализ кода

Статический анализ — это метод проверки программного обеспечения без его выполнения, направленный на поиск дефектов и уязвимостей.

Инструмент Язык Что проверяет
SonarQube Мультиязычный Качество кода, уязвимости, технический долг
ESLint JavaScript, TypeScript Стиль кода, ошибки, лучшие практики
Pylint Python Стиль, ошибки, сложность
Checkstyle Java Стиль кода, стандарты
Fortify Мультиязычный Безопасность кода
Статический анализ должен проводиться на этапе разработки, до запуска тестирования.

3.2 Динамическое тестирование

Динамическое тестирование — это проверка ПО в процессе его выполнения.

Тип тестирования Описание Пример
Модульное (Unit) Проверка отдельных модулей/функций JUnit, PyTest
Интеграционное Проверка взаимодействия между модулями API-тесты
Системное Проверка всей системы End-to-end тесты
Нагрузочное Проверка производительности под нагрузкой JMeter, LoadRunner
Приёмочное (UAT) Проверка заказчиком User Acceptance Testing

3.3 Инструменты тестирования ПО

Инструмент Назначение Поддержка
Selenium Автоматизация веб-тестирования Web
JUnit / TestNG Модульное тестирование Java Java
PyTest Модульное тестирование Python Python
JMeter Нагрузочное тестирование Web, API
Postman Тестирование API API
Jenkins Непрерывная интеграция (CI) Универсальный

3.6 Автоматизация тестирования

Автоматизация тестирования — это использование программных средств для выполнения тестов, сравнения результатов и отчётов.

Преимущества автоматизации:
  • Скорость выполнения тестов
  • Возможность частого запуска (CI/CD)
  • Минимизация человеческих ошибок
  • Регрессионное тестирование
Когда не стоит автоматизировать:
  • Однократные тесты
  • Тесты, требующие визуальной проверки
  • Нестабильные тесты (flaky tests)
Уровень автоматизации Инструменты Пример
Модульные тесты JUnit, PyTest, Mocha Тестирование отдельных функций
API-тесты Postman, RestAssured, Karate Тестирование REST-эндпоинтов
UI-тесты Selenium, Cypress, Playwright Тестирование пользовательского интерфейса
Нагрузочные тесты JMeter, K6, Gatling Тестирование производительности

3.7 Тестирование безопасности

Тестирование безопасности — это процесс выявления уязвимостей и проверки защищённости системы.

Вид тестирования Описание Инструменты
SAST (Static AST) Статический анализ кода на уязвимости SonarQube, Fortify, Checkmarx
DAST (Dynamic AST) Динамический анализ работающего приложения OWASP ZAP, Burp Suite
SCA (Software Composition) Анализ сторонних библиотек и зависимостей OWASP Dependency Check, Snyk
Тестирование проникновения (Pentest) Имитация атак на систему Metasploit, Kali Linux
OWASP Top 10 — ключевой стандарт для тестирования безопасности веб-приложений.

3.8 Управление дефектами

Управление дефектами — это процесс обнаружения, документирования, приоритизации и устранения дефектов.

Статус дефекта Описание
Новый (New) Дефект обнаружен и зарегистрирован
Открыт (Open) Дефект подтверждён и принят в работу
В работе (In Progress) Дефект исправляется
Исправлен (Fixed) Дефект исправлен, ожидает проверки
Закрыт (Closed) Дефект исправлен и проверен
Отклонён (Rejected) Дефект не является ошибкой (не воспроизводится)
Инструменты: Jira, YouTrack, Bugzilla, Redmine.

3.9 Непрерывная интеграция и тестирование (CI/CD)

Непрерывная интеграция (CI) — это практика автоматической сборки и тестирования кода при каждом изменении.

Преимущества CI/CD:
  • Быстрое обнаружение дефектов
  • Ускорение выпуска релизов

3.10 Аудит качества программного обеспечения

Аудит качества ПО — это независимая проверка процессов и продуктов на соответствие установленным требованиям.

Этап аудита Действия
1. Планирование Определение целей, объёма, команды
2. Сбор данных Анализ документации, кода, метрик
3. Оценка Сравнение с критериями качества
4. Выводы Формулирование рекомендаций
5. Отчёт Оформление результатов аудита
Аудит может проводиться как внутренними силами (внутренний аудит), так и внешними организациями.

Тема 4. Управление качеством и сертификация в организации

4.1 Внедрение системы менеджмента качества в ИТ-компании

Внедрение СМК — это системный процесс создания и поддержания системы управления качеством.

Этапы внедрения ISO 9001:
  • Анализ текущих процессов
  • Определение политики и целей в области качества
  • Документирование процессов
  • Внедрение регламентов
  • Обучение персонала
  • Внутренние аудиты
  • Сертификация

4.2 Разработка политики качества

Политика качества — это официальное заявление о намерениях организации в области качества.

Пример политики качества ИТ-компании:

«Мы стремимся создавать программное обеспечение, которое превосходит ожидания клиентов по надёжности, производительности и удобству использования. Мы постоянно улучшаем наши процессы, инвестируем в квалификацию сотрудников и внедряем лучшие практики индустрии».

Политика качества должна быть доведена до всех сотрудников и регулярно пересматриваться.

4.3 Процессный подход к качеству

Процессный подход — это систематическое управление процессами как основой деятельности организации.

Процесс Вход Выход Владелец
Разработка ПО Техническое задание Готовый код Руководитель разработки
Тестирование Код, требования Отчёт о тестировании Руководитель QA
Внедрение Релизный пакет Работающая система DevOps-инженер
Поддержка Запросы пользователей Решённые инциденты Руководитель поддержки

4.4 Документирование процессов качества

Документирование процессов — это фиксация процедур, регламентов и инструкций в письменной форме.

Тип документа Описание Пример
Политика качества Декларация целей «Политика качества ООО Ромашка»
Регламенты процессов Описание порядка действий «Регламент тестирования»
Методики Инструкции по выполнению работ «Методика нагрузочного тестирования»
Записи (Records) Фактические данные о выполнении «Протокол испытаний №1»
Планы качества Документ, определяющий меры по качеству «План качества проекта Альфа»

4.5 Аудит системы менеджмента качества

Аудит СМК — это систематическая, независимая проверка соответствия СМК установленным требованиям.

Тип аудита Описание Периодичность
Внутренний аудит Проводится силами компании 1-2 раза в год
Внешний аудит Проводится сертифицирующим органом Перед сертификацией
Инспекционный контроль Проверка поддержания сертификата 1 раз в год
Результаты аудита: отчёт с несоответствиями и рекомендациями.

4.6 Сертификация по ISO 9001

Сертификация по ISO 9001 — это официальное подтверждение того, что СМК компании соответствует требованиям стандарта.

Преимущества сертификации ISO 9001 для ИТ-компании:
  • Повышение доверия клиентов и партнёров
  • Участие в тендерах и госзакупках
  • Систематизация процессов
  • Повышение эффективности
Сертификат действует 3 года, с ежегодным инспекционным контролем.

4.7 Сертификация по ISO 27001

Сертификация по ISO 27001 — это подтверждение внедрения системы менеджмента информационной безопасности (СМИБ).

Особенно важна для:
  • Компаний, работающих с персональными данными (152-ФЗ)
  • Финансовых организаций
  • ИТ-аутсорсинговых компаний
  • Поставщиков облачных услуг
Процесс сертификации: разработка СМИБ → внедрение → внутренний аудит → сертификационный аудит → получение сертификата.

4.8 Непрерывное улучшение качества (Continuous Improvement)

Непрерывное улучшение — это постоянная деятельность, направленная на повышение эффективности процессов и качества продукции.

Методы непрерывного улучшения:
  • PDCA (Plan-Do-Check-Act) — цикл улучшения
  • Six Sigma — снижение дефектов
  • Lean — устранение потерь
  • Kaizen — малые улучшения
  • Retrospectives — анализ итераций
Этап PDCA Действие в ИТ
Plan Планирование улучшения: сбор данных, анализ, постановка цели
Do Реализация: внедрение изменений, разработка, настройка
Check Проверка: тестирование, мониторинг, анализ результатов
Act Действие: стандартизация успеха, корректировка плана

4.9 Ключевые метрики качества

Категория Метрика Формула
Продукт Плотность дефектов Количество дефектов / KLOC
Время безотказной работы Uptime / (Uptime + Downtime) * 100%
Среднее время отклика Sum(время ответа) / Количество запросов
Процесс Покрытие кода тестами Строки, покрытые тестами / Всего строк * 100%
Время устранения дефекта Дата закрытия — Дата открытия
Стабильность релизов Количество успешных релизов / Всего релизов * 100%
Клиент CSAT (удовлетворённость) Средняя оценка от пользователей
NPS (лояльность) % промоутеров — % критиков
Отток клиентов Клиенты, ушедшие за период / Всего клиентов * 100%

4.10 Оценка эффективности системы менеджмента качества

Оценка эффективности СМК — это измерение степени достижения целей в области качества.

Методы оценки:
  • Анализ достижения целей по качеству
  • Мониторинг жалоб и рекламаций
  • Анализ результатов аудитов
  • Оценка удовлетворённости клиентов
  • Анализ затрат на качество
Эффективность СМК должна оцениваться не реже 1 раза в год (при анализе со стороны руководства).
Показатель эффективности Формула Целевое значение
Индекс выполнения плана качества Выполненные цели / Всего целей * 100% > 80%
Тренд по дефектам Количество дефектов в релизе Снижение от релиза к релизу
Удовлетворённость клиентов Средний балл по опросам > 4.5 из 5
Затраты на качество Бюджет QA / Общий бюджет * 100% 10-15%
